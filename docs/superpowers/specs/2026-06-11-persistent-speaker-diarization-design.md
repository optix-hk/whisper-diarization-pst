# Persistent Speaker Diarization Design

## Problem

The whisper-diarization pipeline assigns speakers ephemeral integer IDs (`Speaker 0`, `Speaker 1`, ...) per run. These IDs are not stable across runs — running the same audio twice can produce different numbering, and there is no way to recognize that a speaker in file A is the same person in file B. Speaker embeddings are generated by NeMo's TitaNet model during diarization but discarded immediately after.

## Solution

Add a post-diarization stage that extracts per-speaker mean embeddings from NeMo's internal state, matches them against a persistent SQLite database of known speaker profiles, and relabels speakers with their persistent names instead of arbitrary integers.

## Approach

**Post-diarization embedding extraction** (Approach 1 from brainstorming): After NeMo's MSDD diarization completes, we extract the cluster-average embeddings that NeMo already computes internally, match them against stored profiles, and relabel the output. The diarization pipeline itself is untouched.

Alternative approaches considered:
- Embedding-first pipeline (pre-seed clustering with known profiles) — rejected due to deep NeMo coupling and fragility
- Hybrid (post-match + pre-seed hints) — rejected as YAGNI; can be added later

## Scope

**MSDD backend only.** TitaNet embeddings are already part of the MSDD pipeline. Sortformer is an end-to-end model without exposed embeddings; adding an embedding model alongside it would negate its lighter footprint. This can be revisited if Sortformer gains embedding support.

## Architecture

### Updated Pipeline

```
Stage 1-4: Unchanged (Source Sep → Transcription → Forced Alignment → Diarization)
Stage 4.5 (NEW): Speaker Embedding Matching
  ├── Extract per-speaker mean embeddings from NeMo's internal state
  ├── Compare each mean embedding against stored profiles in SQLite
  ├── Match speakers above minimum cosine similarity threshold
  ├── For unmatched speakers: auto-assign label or prompt interactively
  └── Update stored profiles with matched/new embeddings
Stage 5-7: Unchanged (Word mapping, punctuation, output)
```

The new stage is a pure post-processing layer. The diarization output (`speaker_ts`) is remapped from integer IDs to persistent labels, then the rest of the pipeline uses those labels unchanged.

### New Components

| Component | Responsibility |
|---|---|
| `SpeakerEmbeddingStore` | SQLite-backed storage for speaker profiles |
| `SpeakerMatcher` | Pure-function cosine similarity matching |
| `PersistentSpeakerDiarizer` | Orchestrates extraction, matching, labeling, storage |
| `speakerctl.py` | CLI tool for managing speaker profiles |

### Data Flow

```
NeuralDiarizer.diarize()
  → DiarizationResult(speaker_ts, speaker_embeddings)
  → PersistentSpeakerDiarizer.resolve_speakers(result, word_speaker_mapping)
    → SpeakerMatcher.match_speakers(embeddings, store, threshold)
      → for each speaker: cosine_similarity(new_emb, stored_embs) → best match
    → for matches: store.update_embedding(name, emb)
    → for new speakers: store.add_speaker(auto_label | interactive_label, emb)
    → return {speaker_id: persistent_name}
  → apply_persistent_labels(speaker_ts, label_map)
  → rest of pipeline uses persistent labels
```

## Component Details

### SpeakerEmbeddingStore (SQLite)

**Database location**: `~/.whisper-diarization/speakers.db` (configurable via `--speaker-db`)

**Schema** — single table `speakers`:

| Column | Type | Description |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | Internal row ID |
| `name` | TEXT UNIQUE NOT NULL | User-facing label (e.g., "Alice", "Bob") |
| `embedding` | BLOB NOT NULL | Serialized mean embedding (192-dim float32 → 768 bytes via numpy `tobytes()`) |
| `sample_count` | INTEGER DEFAULT 1 | Number of embeddings averaged into the current mean |
| `created_at` | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | First time this speaker was seen |
| `updated_at` | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | Last time embedding was updated |

**Key operations**:

- `get_all_profiles()` → List of `(id, name, embedding_np, sample_count)`
- `find_best_match(embedding, min_threshold=0.6)` → `(name, similarity_score)` or `(None, 0.0)` if no match above threshold
- `add_speaker(name, embedding)` → Inserts new profile
- `update_embedding(name, new_embedding)` → Running average: `new_mean = (old_mean * old_count + new_embedding) / (old_count + 1)`, increments `sample_count`
- `rename_speaker(old_name, new_name)` → Updates name
- `delete_speaker(name)` → Removes profile
- `list_speakers()` → All names + created/updated timestamps

**Design choices**:

- Embeddings stored as raw float32 bytes (768 bytes per speaker) — compact, fast to deserialize via `np.frombuffer()`
- Running average with `sample_count` avoids storing all historical embeddings
- `min_threshold` default of 0.6 is conservative; tunable via `--match-threshold`
- SQLite file is created lazily on first write; read-only if only matching

### SpeakerMatcher

Pure function, no state:

```python
def match_speakers(
    speaker_embeddings: Dict[int, np.ndarray],
    store: SpeakerEmbeddingStore,
    min_threshold: float = 0.6,
) -> Dict[int, Tuple[Optional[str], float]]
```

Logic:

1. Load all stored profiles from the store
2. For each new speaker's mean embedding, compute cosine similarity against every stored embedding
3. Pick the highest similarity score. If above `min_threshold`, it's a match
4. If below `min_threshold`, the speaker is "new" (no match)
5. If two new speakers both match the same stored profile, the higher-score one wins; the other is treated as new

### Embedding Extraction from NeMo

After `NeuralDiarizer.diarize()` completes, before the temp directory is cleaned up, we access:

```python
model.clustering_embedding.emb_sess_test_dict
```

This is `Dict[int, Dict[str, Dict]]` where each entry has `'avg_embs'`: a `Tensor(192, num_speakers)` — one 192-dim mean embedding per detected speaker, already computed by NeMo's clustering step.

**API change to MSDDDiarizer**: The `diarize()` method currently returns `List[Tuple[int, int, int]]`. It is extended to return a `DiarizationResult` dataclass:

```python
@dataclass
class DiarizationResult:
    speaker_ts: List[Tuple[int, int, int]]
    speaker_embeddings: Dict[int, np.ndarray]
```

Callers that don't need embeddings (e.g., `--no-persist` mode) can ignore them. The persistent matching layer consumes them.

### PersistentSpeakerDiarizer (Orchestrator)

```python
class PersistentSpeakerDiarizer:
    def __init__(self, store: SpeakerEmbeddingStore, min_threshold: float = 0.6, interactive: bool = False):
        ...

    def resolve_speakers(
        self,
        result: DiarizationResult,
        word_speaker_mapping: Optional[List[Dict]] = None,
    ) -> Dict[int, str]:
```

**`resolve_speakers()` flow**:

1. For each speaker in `result.speaker_embeddings`, call `SpeakerMatcher.match_speakers()` against the store
2. For matched speakers: collect the mapping `{speaker_id: stored_name}`
3. For unmatched speakers: auto-assign label `"Speaker N"` where N is the next available integer not already in the store. If `interactive=True`, prompt the user: `"New speaker detected (1:23.4s - 1:45.2s): "I think we should go with option B." Enter name [default: Speaker 3]: "` — the prompt includes the first full sentence spoken by that speaker (extracted from `word_speaker_mapping` when provided), plus the segment timestamps
4. Add all new speakers to the store via `store.add_speaker()`
5. Update all matched speakers' embeddings via `store.update_embedding()`
6. Return the mapping `{speaker_id: persistent_label}`

### Applying Persistent Labels

A simple function in `helpers.py`:

```python
def apply_persistent_labels(speaker_ts, label_map: Dict[int, str]) -> List[Tuple[int, int, str]]:
    return [(start, end, label_map[spk_id]) for start, end, spk_id in speaker_ts]
```

This converts integer speaker IDs to persistent labels. Downstream functions (`get_words_speaker_mapping`, `get_sentences_speaker_mapping`, etc.) already handle string speaker labels. The key change is in `get_sentences_speaker_mapping` and `get_speaker_aware_transcript`: when `spk` is already a named string (not an integer), skip the `"Speaker {spk}"` formatting and use the label directly.

## CLI Interface

### New arguments for `diarize.py`

| Argument | Default | Description |
|---|---|---|
| `--speaker-db` | `~/.whisper-diarization/speakers.db` | Path to speaker profile database |
| `--match-threshold` | `0.6` | Minimum cosine similarity to match a known speaker |
| `--interactive` | `False` | Prompt for new speaker names instead of auto-labeling |
| `--no-persist` | `False` | Disable persistent speaker matching (original behavior) |

### New standalone CLI tool: `speakerctl.py`

```
speakerctl.py list              # List all stored speakers
speakerctl.py rename <old> <new>  # Rename a speaker
speakerctl.py delete <name>     # Delete a speaker profile
speakerctl.py show <name>       # Show speaker details (created, updated, sample count)
```

## Error Handling

- **SQLite locked**: Retry with exponential backoff (3 attempts). Not expected under single-user CLI usage.
- **No speakers in database**: All speakers are treated as new. First run populates the database.
- **Corrupt database**: Raise a clear error with instructions to delete the `.db` file and re-run.
- **Temp directory cleaned before embedding extraction**: This is prevented by design — embeddings are extracted inside the `with tempfile.TemporaryDirectory()` block before it exits.
- **Interactive mode with no TTY**: Fall back to auto-labeling with a warning.

## Testing Strategy

- `SpeakerEmbeddingStore`: Unit tests with in-memory SQLite (`:memory:`), covering all CRUD operations, running average updates, and find_best_match with known embeddings
- `SpeakerMatcher`: Unit tests with synthetic embeddings (known cosine similarities), testing match/no-match/ambiguous cases
- `PersistentSpeakerDiarizer`: Integration tests with mock store and matcher, testing the full resolve flow including interactive mode
- End-to-end: Manual testing with sample audio files across multiple runs to verify speaker persistence
